# Auditoría de Seguridad — 2026-08-24

## Contexto

Auditoría pre-publicación del repositorio como público en GitHub, orientada a screening por recruiters técnicos. Objetivo: descartar exposición de secretos, credenciales o datos sensibles en el historial de git, y resolver deuda técnica de seguridad en dependencias (DT-09-01).

## 1. Escaneo de secretos en historial de git

**Método:**
```bash
git log --all --full-history -- .env
git log -p --all -- .env | grep -i "service_id|template_id|public_key"
git log -p --all | grep -iE "api[_-]?key|secret|password|token|sk-|pk_live|AIza"
```

**Resultado:** ✅ Limpio. `.env` nunca existió en el historial de commits (ni el archivo ni sus valores). Los matches de "token" en el historial corresponden a design tokens (paleta de colores CSS del design system), no a credenciales.

## 2. Verificación de `.gitignore`

**Resultado:** ✅ Correcto. `.env`, `.env.local`, `.env.*.local` cubiertos. Confirmado con `git status --ignored` que los archivos locales están excluidos del tracking.

## 3. npm audit

**Antes:** 26 vulnerabilidades (3 low, 6 moderate, 17 high)

**Clasificación:**
- La mayoría eran devDependencies (vite, eslint, rollup, postcss, sharp, etc.) — sin exposición runtime, riesgo real nulo para usuarios finales del sitio.
- `path-to-regexp` (DT-09-01 original): confirmado dev-only, vía `eslint → @modelcontextprotocol/sdk → express → router`. Nunca llegó al bundle de producción; la atribución original a react-router era incorrecta.
- `react-router-dom` y `dompurify`: única dependencias runtime afectadas, en la raíz de `dependencies`.

**Acciones:**
```bash
npm audit fix --legacy-peer-deps   # 26 → 3 (resolvió react-router-dom, dompurify, brace-expansion parcial)
npm audit fix --legacy-peer-deps   # 3 → 2 (brace-expansion resuelto)
npm audit fix --force              # 2 → 0 (sharp 0.34→0.35, vite-imagetools 9→12, breaking pero dev-only)
```

**Después:** ✅ 0 vulnerabilidades.

**Validación post-fix:**
- `npm run build`: exitoso, 552 módulos, sitemap generado (28 URLs)
- `npm run test`: 72/72 tests passing (previamente documentado como 71/71 — se sumó 1 test sin actualizar el conteo en docs)

## 4. Datos personales hardcodeados

**Hallazgo:** email personal (`[email personal]`) hardcodeado como `to_email` en el flujo de EmailJS — identificado en auditoría previa (AUDIT_2026-06-15).

**Estado:** ✅ Ya resuelto en código antes de esta auditoría (`Contact.jsx`, `AgenciasCTAFinal.jsx`, `AgenciasHero.jsx` usan `import.meta.env.VITE_CONTACT_EMAIL`; `.env.example` con placeholder). El hallazgo en `AUDIT_2026-06-15.md` había quedado desactualizado respecto al código.

**Acción adicional:** email personal en `docs/specs/FEATURE-00_PROJECT_SETUP/prd.md` (documentación, no código) reemplazado por referencia genérica al formulario de contacto, para reducir exposición a scraping si el repo pasa a público.
