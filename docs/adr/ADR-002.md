# ADR-002 — JavaScript puro sin TypeScript

**Fecha:** 10 de Abril de 2026
**Estado:** Aceptado

## Contexto
Portfolio personal de alcance acotado (~30 componentes), un solo desarrollador. Se evaluó si agregar TypeScript era justificado para detectar errores de tipo en compilación.

## Alternativas consideradas
| Alternativa | Pro | Contra |
|-------------|-----|--------|
| TypeScript completo | Type-safety, mejor DX en IDE | Setup complejo, overhead de compilación, migración costosa |
| PropTypes | Validación en runtime | Menos expresivo que TypeScript, overhead de bundle |
| JSDoc con type hints | Ligero, sin setup | Sin validación en compilación |

## Decisión
**JavaScript puro (ES2020+)** porque:
- Overhead de configuración y migración no justificado para el tamaño actual
- Un solo desarrollador puede mantener disciplina manual
- ESLint cubre la mayoría de casos de error
- React 19 tiene mejor soporte para JavaScript dinámico

## Consecuencias
**Positivas:**
- Setup más simple, menor configuración
- Desarrollo más rápido (sin paso de compilación)
- Bundle más pequeño (sin tipos)
- Mayor flexibilidad para cambios rápidos

**Negativas / Deuda asumida:**
- Sin detección de errores de tipo en compilación
- Refactoring manual más propenso a errores
- Onboarding de colaboradores requiere documentación explícita

## Revisión sugerida
Si el proyecto supera 60 componentes, suma colaboradores permanentes, o la complejidad de state management aumenta significativamente, migrar a TypeScript.
