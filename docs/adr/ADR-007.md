# ADR-007: English as Canonical Locale at Root (`/`)

**Status**: Accepted
**Date**: 2026-06-05
**Branch**: `feature/seo-aeo-i18n-button`
**Feature**: `specs/features/001-i18n-url-routing/spec.md`
**Supersedes**: —
**Related**: ADR-006, ADR-010, ADR-011

---

## Context

Given the URL-based routing architecture established in ADR-006, a canonical locale must be assigned to the root path `/`. Two options existed:

| Option | Root `/` language | `/es` language |
|--------|------------------|----------------|
| **A — Spanish canonical** | Spanish (current state) | English |
| **B — English canonical** | English | Spanish |

The portfolio's stated business objective is to capture clients in the US and European markets. The root path (`/`) carries the highest domain authority signal and is the URL most likely to be shared, linked externally, and indexed without a path qualifier. Assigning the root to English maximizes the signal strength for the primary target market.

Additionally, the `x-default` hreflang tag — used by Google to indicate the fallback URL for users whose language is not explicitly listed — must point to `/`. Assigning `x-default` to an English URL aligns with international best practice for portfolios targeting non-specific locales.

Spanish-speaking visitors are served correctly at `/es`. There is no user experience degradation — the `LangSwitcher` component is visible immediately on load.

---

## Decision

English is the canonical locale. It is served at the root path `/` with no redirect.

- `<html lang="en">` is set in `index.html` as the base document attribute
- All meta tags in `index.html` are authored in English
- `hreflang="x-default"` points to `/` (English)
- `hreflang="en"` points to `/`
- `hreflang="es"` points to `/es`
- Spanish content requires the `/es` prefix — there is no automatic detection or redirect based on `Accept-Language` headers

---

## Consequences

**Positive**:
- Maximum SEO signal strength for US/EU market on the highest-authority path
- `x-default` hreflang correctly points to the English root — standard international configuration
- Simpler crawl budget allocation: Googlebot's first crawl of the domain lands on English content
- No redirect chain from root to a locale path — zero latency penalty for the primary conversion path

**Negative / Trade-offs**:
- Spanish-speaking visitors landing on `/` see English by default. Mitigation: `LangSwitcher` is visible in the header on all routes; no auto-redirect is applied
- No `Accept-Language` detection: a browser set to `es-AR` will not auto-redirect. This is intentional — auto-redirects based on browser headers cause crawlability issues (Googlebot does not send locale-specific headers by default)

**Neutral**:
- The previous site was entirely in Spanish. This decision represents a complete language inversion of the default experience. Content migration (translation) is a parallel track and is out of scope for Feature 001 engineering tasks

---

## Alternatives Rejected

**Option A (Spanish canonical at `/`)**: Rejected because it inverts the indexability benefit. The root path would be indexed in Spanish, and the English version — targeting the primary conversion market — would sit at `/en` with reduced domain authority signal. This produces the opposite of the intended SEO outcome.

**Auto-detection via `Accept-Language`**: Rejected for two reasons. First, Googlebot crawls without locale-specific headers, meaning auto-detection would cause inconsistent crawl results. Second, it introduces server-side or JavaScript detection logic that conflicts with the URL-as-source-of-truth principle established in ADR-011.
