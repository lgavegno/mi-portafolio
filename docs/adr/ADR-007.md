# ADR-007: Spanish as Default Canonical Locale

**Date:** 2026-06-05 (revised 2026-06-08)
**Status:** Accepted (supersedes original EN-default decision)
**Feature:** FEATURE-01 — i18n URL-Based Routing

## Context

The portfolio targets Argentine and Latin American SME clients as the primary
market. Spanish is the native language of the target audience. English is
available as a secondary locale for international recruiters and clients.

## Decision

Spanish (`es`) is the canonical locale served at the root path `/` with no
redirect. English is the secondary locale served at `/en` and all sub-paths
(`/en/blog`, `/en/works/:slug`, etc.).

When the user switches to English, ALL content switches to English without
exception — navigation, hero, services, works, contact, blog, and data.

## Consequences

**Positive:**
- Primary audience (Argentine SMEs) lands on Spanish by default — no action required
- English available at `/en` for international visitors
- URL structure is clean and predictable

**Negative:**
- Breaking change from original EN-default architecture — requires updating
  App.jsx, LangSwitcher, vercel.json, and all internal links
- hreflang canonical tag now points to `/` (ES) — EN alternate at `/en`

## Alternatives Rejected

- **EN as default (`/` = EN, `/es` = ES):** Original decision, rejected because
  primary market is Spanish-speaking. International SEO is secondary objective.
- **Client-side toggle:** Rejected per ADR-006 — URL is single source of truth.

## Impact on Other ADRs

- ADR-006: Unchanged — URL-based routing still applies
- ADR-011: Unchanged — URL is still single source of truth
- spec.md and vercel.json must be updated to reflect `/en` prefix for English
