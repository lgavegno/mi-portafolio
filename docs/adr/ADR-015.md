# ADR-015: Presentation Content Lives Outside LocaleProvider

**Status**: Accepted
**Date**: 2026-11-07
**Branch**: `feature/odoo-dux-solutions`
**Feature**: `docs/specs/FEATURE-12_ODOO_DUX_SOLUTIONS/spec.md`
**Supersedes**: —
**Related**: ADR-010, ADR-013, ADR-014

---

## Context

FEATURE-12 adds a chaptered presentation (7 Odoo slides + 5 Dux slides) in three
locales. `LocaleProvider` statically imports every locale module for `es`, `en`
and `pt`, so anything registered there ships in the entry chunk that renders the
hero. Baseline entry chunk (2026-11-07): `index-*.js.br` = 83,943 bytes.

The presentation is shown only after a user clicks a door in the hero or opens
`/odoo` / `/dux`. Putting ~12 slides × 3 languages in the entry chunk would add
weight to the LCP path for every visitor, most of whom never open it.

The project already has a precedent for long, per-locale content outside
`LocaleProvider`: `features/blog/data/blogData.{es,en,pt}.js` and
`data/projects.{es,en,pt}.js`.

## Decision

- **Short UI strings** (door strip, section header, carousel controls, WhatsApp
  message templates, page meta, disclaimer) live in
  `src/locales/{es,en,pt}/solutions.js`, are registered in `LocaleProvider` as
  `t.solutions`, and are read only through `useLocale()`.
- **Slide content** lives in `src/features/solutions/data/slides.{es,en,pt}.js`.
  The lazily loaded `SolutionsSection` imports only the active locale with a
  dynamic `import()`, so the content never reaches the entry chunk.
- Slide data carries stable `id` and `ref` fields; refs are locale-independent.
- Interpolation uses a tiny pure helper (`formatTemplate`), keeping ADR-010
  (no i18n library) intact.

## Consequences

- ✅ Entry chunk grows only by the short UI strings (target ≤ 3 KB brotli).
- ✅ Visitors download one locale of slide content, and only on demand.
- ⚠️ Two places hold the feature's text; a data-integrity test keeps slide
  structure and refs in parity across locales.
- ⚠️ PT content follows ADR-014 (review marker until Leo approves it).
