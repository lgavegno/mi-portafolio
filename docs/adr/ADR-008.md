# ADR-008: PNG Estático como og:image

**Status**: Accepted
**Date**: 2026-06-05
**Branch**: `feature/seo-aeo-i18n-button`
**Feature**: `FEATURE-02_SEO_METATAGS`
**Supersedes**: —
**Related**: ADR-006, ADR-009

---

## Context

The portfolio requires a social graph image (og:image) for sharing on LinkedIn, X (Twitter), WhatsApp, and other platforms. Open Graph scrapers consume the og:image meta tag to render a preview card when a user shares a link.

Three options were evaluated:

| Option | Description | Compatibility |
|--------|-------------|---|
| **A — SVG Asset** | Use `benefag-branding.svg` as og:image. Dynamic, maintainable, single file. | ❌ LinkedIn, X, WhatsApp do not reliably parse SVG. Scrapers fall back to favicon or blank. |
| **B — Dynamic Generation** | Generate PNG at request time or build time. Better control over final pixels. | ⚠️ Adds runtime dependency (e.g., `sharp`, `playwright`), increases bundle size, introduces build complexity. |
| **C — Static PNG Asset** | Copy `benefag-branding.png` to `public/og-image.png` and reference in meta tags. Simple, universal, no dependencies. | ✅ Universal support across all social platforms and Open Graph consumers. |

SVG og:image fails silently on major platforms; dynamic generation adds unnecessary complexity for a portfolio where the branding image rarely changes. Option C (static PNG) is the only pragmatic choice.

---

## Decision

Use a static PNG asset (`public/og-image.png`, 1200×630 pixels) as the official Open Graph image.

- Copy `benefag-branding.png` to `public/og-image.png` during development
- Reference in all HTML meta tags: `<meta property="og:image" content="https://[domain]/og-image.png">`
- Dimensions: 1200×630 (standard OG aspect ratio, supported by all platforms)
- Format: PNG (lossless, supports transparency, universally parsed)
- No runtime generation, no build-time conversion dependencies

---

## Consequences

**Positive**:
- Universal compatibility with LinkedIn, X, WhatsApp, Facebook, Discord, and all Open Graph consumers
- Zero runtime or build-time dependencies; no additional npm packages required
- Fast delivery: static asset served directly from CDN (Vercel)
- Image is immutable and cacheable with aggressive HTTP headers
- Explicit control: no magic or automation that could fail silently

**Negative / Trade-offs**:
- Manual update required if branding image changes (no automated pipeline)
- File duplication: `benefag-branding.png` exists in source, copied to `public/og-image.png` for distribution
- Cannot personalize og:image per-page (same image for all routes)

**Neutral**:
- PNG format is smaller than SVG for branded assets (~50–100 KB typical)
- 1200×630 aspect ratio is the standard and universally recognized

---

## Alternatives Rejected

**Option A (SVG)**: SVG og:image is not supported by any major social platform. Testing on production confirmed that LinkedIn, X, and WhatsApp either reject the og:image or fall back to favicon. This option is non-viable regardless of other considerations.

**Option B (Dynamic Generation)**: While theoretically powerful (e.g., per-page titles, dynamic text), it introduces a build or runtime dependency, increases complexity, and is unnecessary for a portfolio where the image is static branding. The cost (added package, build step, potential failures) far outweighs the benefit.
