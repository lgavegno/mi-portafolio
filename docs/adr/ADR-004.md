# ADR-004 — Arquitectura feature-based (DDD Light)

**Fecha:** 10 de Abril de 2026
**Estado:** Aceptado

## Contexto
Portfolio con múltiples secciones independientes (hero, blog, contact, services, works, analytics) que podrían crecer, cambiar o eliminarse individualmente. Se evaluó si una estructura tradicional por tipo era suficiente.

## Alternativas consideradas
| Alternativa | Pro | Contra |
|-------------|-----|--------|
| Estructura por tipo (components/, hooks/, utils/) | Simplicidad inicial | Acoplamiento, escalabilidad limitada, context switching |
| Atomic Design | Componentes reutilizables | Verboso, no agrupa lógica de negocio |
| Monorepo con packages | Escalabilidad máxima | Over-engineering para un portfolio |

## Decisión
**Feature-Based Architecture (DDD Light)** organizada como:
```
src/
├── components/          # UI Kit global (Button, Header, Footer, etc.)
├── features/            # Módulos de negocio autocontenidos
│   ├── hero/
│   ├── blog/
│   ├── contact/
│   ├── services/
│   ├── works/
│   └── analytics/
├── layouts/             # Composición de páginas
├── pages/               # Rutas / puntos de entrada
└── config/              # Constantes y configuración
```

Cada feature es autocontenida: componentes, hooks, data, CSS propios.

## Consecuencias
**Positivas:**
- Escalabilidad clara: agregar features no aumenta complejidad cognitiva
- Mantenibilidad: código relacionado colocado junto
- Desacoplamiento: features no dependen unas de otras
- Onboarding más fácil: cada sección es un contexto independiente
- Facilita paleo de features (remover blog sin afectar contact)

**Negativas / Deuda asumida:**
- Cierta duplicación de patrones entre features (hooks, state)
- Requiere disciplina para no permitir imports circulares
- Componentes globales (ui/) pueden crecer desorganizados

## Revisión sugerida
Si se integra un CMS (Strapi, Contentful), migrar a Next.js App Router.
Si el proyecto suma team de 3+ desarrolladores, considerar monorepo con packages.
