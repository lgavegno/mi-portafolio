# ADR-003 — EmailJS para formulario de contacto

**Fecha:** 10 de Abril de 2026
**Estado:** Aceptado

## Contexto
Se necesita formulario de contacto funcional que envíe emails sin infraestructura de servidor propia. El volumen esperado es bajo (< 100 contactos/mes).

## Alternativas consideradas
| Alternativa | Pro | Contra |
|-------------|-----|--------|
| Backend Node.js propio | Control total, sin dependencias externas | Hosting, mantenimiento, costo |
| Formspree | Setup mínimo | Rate limiting bajo en tier gratuito |
| Netlify Forms | Integración nativa con Vercel | Vendor lock-in |
| AWS SES | Escalable | Configuración compleja, costo |

## Decisión
**EmailJS Browser v4.4.1** porque:
- Tier gratuito: 200 emails/mes (suficiente)
- Credenciales viven en variables de entorno: `VITE_EMAILJS_PUBLIC_KEY`
- Cliente-side, sin backend
- GDPR-compliant (sin almacenamiento en EmailJS)
- Integración simple en `src/features/contact/Contact.jsx`

## Consecuencias
**Positivas:**
- Costo $0 en fase inicial
- Configuración mínima (API key en .env)
- Mantenimiento cero
- No requiere base de datos

**Negativas / Deuda asumida:**
- Sin rate limiting real en cliente (vulnerable a spam)
- Dependencia de servicio externo (EmailJS)
- Sin almacenamiento de leads (logs solo en EmailJS)
- Límite de 200 emails/mes en tier gratuito

## Revisión sugerida
- Si el volumen supera 500 emails/mes, migrar a plan pago o backend propio
- Si se requiere CRM o lead tracking, implementar backend Node.js con MongoDB
