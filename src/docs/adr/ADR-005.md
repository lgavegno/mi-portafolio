# ADR-005 — Testing Framework: Vitest + React Testing Library

**Fecha:** 2026-05-13
**Estado:** Propuesto (Fase 2)
**Impacto:** Testing strategy, quality assurance, portfolio credibility

---

## Contexto

Portfolio con 0% test coverage. Deuda técnica crítica para demostrar expertise senior.

Opciones evaluadas:
1. Jest (estándar, amplio soporte)
2. Vitest (Vite-native, más rápido, ESM first)
3. Testing Library (component testing)
4. Cypress/Playwright (E2E)

**Constraint:** Minimizar overhead en Vite build + dev server.

---

## Alternativas consideradas

| Alternativa | Pro | Contra | Recomendación |
|-------------|-----|--------|------|
| **Jest** | Estándar de facto, amplio soporte, maduro | Más lento (CommonJS), requiere transpilación, overhead | ⚠️ Pasado |
| **Vitest** | Vite-native, ESM first, rápido, drop-in Jest replacement | Menos maduro, comunidad más pequeña | ✅ **Elegido** |
| **Testing Library** | Encourages user-centric testing, excelente para React | No es framework, es utilería (usada con Jest/Vitest) | ✅ **Complementario** |
| **Cypress** | Excelente para E2E, debugging visual | Pesado, overhead en CI/CD | ⏳ **Fase 4** |
| **Playwright** | E2E moderno, rápido | Curva de aprendizaje | ⏳ **Alternativa Phase 4** |

---

## Decisión

**Vitest + React Testing Library + Vitest UI (opcional)**

### Setup Phase 2

## Consecuencias

### Positivas

✅ **Fast execution:** Vitest es 5-10x más rápido que Jest en CI/CD
✅ **HMR compatible:** Watch mode integra con Vite dev server
✅ **ESM native:** Usa módulos ES directamente, sin transpilación
✅ **Jest compatibility:** Sintaxis idéntica (describe, it, expect)
✅ **TDD workflow:** Rápido feedback en desarrollo
✅ **Portfolio credibility:** >70% coverage + UC tests demuestran expertise
✅ **Drop-in replacement:** Si migrar a Jest, cero cambios en tests

### Negativas / Deuda asumida

⚠️ **Menos maduro:** Comunidad menor que Jest, menos plugins
⚠️ **Ecosystem gaps:** Algunos esotéricos plugins no soportados
⚠️ **Breaking changes:** Posibles actualizaciones mayores en Vitest
⚠️ **Team ramp-up:** Dev nuevo necesita aprender Vitest CLI
⚠️ **CI/CD setup:** GitHub Actions requiere configuración manual

---

## Trade-offs justificados

**Por qué Vitest over Jest:**
- 🚀 5-10x faster build + test execution
- 📦 Integración con Vite (no double-build)
- 🎯 ESM-first → alineado con React 19 + Vite stack
- 💡 Drop-in Jest replacement → bajo riesgo de migración

**Por qué Testing Library over Enzyme:**
- 🎯 User-centric testing (más valor pedagógico)
- ✅ Recomendado por React core team
- 🔍 Mejores prácticas explícitas (testing behavior, no implementation)

**Por qué NO E2E en Phase 2:**
- ⏱️ Too early (need unit tests first)
- 🎯 UC-01 integration tests suficientes
- 📅 Phase 4: Playwright + Core Web Vitals audit
